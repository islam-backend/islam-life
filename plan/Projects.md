# 🚀 خطة التحديث v16.0 — ترقية النظام وإغلاق الثغرات البرمجية والتحكم التفاعلي (Feature Expansion & System Stability Plan)

تستهدف هذه الخطة توسيع إمكانيات إدارة المشاريع والمهام عبر دعم المرفقات البصرية والروابط الخارجية، وحل المشاكل التقنية المتعلقة بالتواريخ وإعادة تحميل الصفحة، مع إحكام السيطرة البصرية والأمنية على آلية السحب والإفلات وتطابق حركات الـ Hover.

---

## 💾 1️⃣ توسيع بيانات المهام والمشاريع (Task Attachments & Project Links)

### أ. دعم رفع واستقبال الصور داخل التاسك (Task Image Support)
* **إضافة حقل المرفقات:** تعديل نافذة أو واجهة إضافة التاسك لتدعم زر مدمج وبسيط لرفع صورة (`Image Upload`).
* **التخزين والعرض:** يتم رفع الصورة وتخزينها في الـ Firebase Storage، وحفظ الرابط الخاص بها داخل مستند المهمة في Firestore لتعرض كصورة مصغرة مدمجة (Thumbnail) بحواف حادة داخل كارت التاسك عند توفرها.

### ب. حقول الروابط المخصصة بالمشروع (Custom Project Quick Links)
* **إضافة حقول مرنة:** إضافة سكشن مدمج وعالي الكثافة (High-Density) داخل كرت المشروع يستقبل روابط العمل الخارجية (مثل: لينكات Figma أو مستندات برمجية).
* **إدخال مخصص (Label & Value):** يتيح النظام للمستخدم كتابة عنوان الرابط (Label - مثل: "تصميم فيجما") وقيمة الرابط (Value - URL) وحفظها ديناميكياً داخل كولكشن المشاريع لسهولة الوصول السريع بضغطة زر.

## 🐛 2️⃣ معالجة العيوب والحلول الهندسية (Stability & Bug Fixes)

### أ. حل مشكلة ترحيل التاريخ لليوم السابق (Timezone / Date Offset Fix)
* **السبب والحل:** معالجة المشكلة التي تتسبب في تسجيل اليوم الفعلي ناقصاً يوماً واحداً (تسجيل يوم 4 فيظهر يوم 3)؛ الناتجة عن فروق التوقيت وفقدان معايير الـ ISO أثناء تحويل التواريخ. سيتم إجبار النظام على استخدام التوقيت المحلي الصريح (Local Midnight) وتثبيت التاريخ المختار بالملي قبل إرساله لـ Firestore.
* **إلغاء الـ Quick Reload المتكرر بالشاشة (Snapshot Debouncing)**
* **سبب الأزمة:** التطبيق يقوم بعمل إعادة تحميل سريعة ومتكررة ومزعجة للواجهة بسبب استدعاءات عشوائية أو تكرار الاستماع اللحظي (`onSnapshot`) عند حدوث أي تغيير طفيف في حقول الساعات أو الترتيب.
* **الحل:** مواءمة وتحديد قنوات الاستماع لـ Firestore برمجياً وتفعيل الـ `Debounce/Mute` لمنع ركض الشاشة وإعادة البناء عشوائياً بدون تغيير جذري حقيقي.

## 🎨 3️⃣ تجربة المستخدم والتحكم الشجري التفاعلي بالتقويم (Visual Matching & Drag Security)

### أ. توحيد استايل الـ Hover بكروت التقويم
* تعديل تأثير التمرير (Hover) لكروت تفاصيل اليوم داخل التقويم ليتطابق بصرياً 100% مع حركة ونعومة الـ Hover الموجودة بكروت صفحة إدارة العملاء، حفاظاً على التناسق الحركي الموحد للنظام.

### ب. قفل أمن التاسكات ومنع التنقل الخارجي بالتقويم
* **حظر النقل بين المشاريع:** كتابة شرط صارم يمنع نهائياً سحب أو إفلات أي تاسك خارج مربع مشروعها الأصلي في واجهة التقويم لمنع تداخل واختلاط المهام بين المشاريع المختلفة.
* **إعادة الترتيب الأفقي للكروت الكبيرة:** تفعيل السحب والإفلات لكروت المشاريع الكبيرة نفسها (العملاء والمشاريع) لتتيح للمستخدم ترتيب المربعات أفقياً يميناً ويساراً فقط لتنظيم أولوية العرض.

---

## 🔄 4️⃣ آلية إعادة الترتيب الداخلي للتاسكات بصفحة المشروع (Intra-Status Task Reordering)

* **الترتيب الداخلي للحالة (Internal Drag & Drop):** تفعيل خاصية السحب والإفلات الرأسي لكروت التاسكات بداخل صفحة المشروع الأساسية.
* **إعادة الترتيب فقط:** تتيح هذه الميزة للمستخدم سحب التاسك لأعلى أو لأسفل **داخل نفس العمود ونفس الحالة الحالية** لتغيير ترتيب أولويتها ببعضها البعض، مع تحديث رقم الترتيب (`orderIndex`) الخاص بالتاسك صامتاً في قاعدة البيانات دون تغيير حالتها العامة.

## 🛠️ 5️⃣ خطوات التنفيذ المحددة (Action Items لـ Claude)

- [ ] **أولاً:** دمج حقل رفع الصور وإضافته لبيانات التاسك، وتهيئة بوكس الروابط المخصصة (Label/Value) في واجهة المشروع.
- [ ] **ثانياً:** إصلاح دالة تحويل التاريخ لتعمل بالتوقيت المحلي لحل مشكلة ترحيل اليوم، ومراجعة مستمعي الـ Firestore لإلغاء الـ Quick Reload المتكرر.
- [ ] **ثالثاً:** ضبط كود الـ CSS للـ Hover بكروت التقويم ومطابقتها بصفحة العملاء.
- [ ] **رابعاً:** إغلاق ثغرة الـ Drag بالتقويم لمنع نقل التاسكات لمشاريع أخرى، وتفعيل السحب الأفقي لكروت المشاريع الكبيرة.
- [ ] **خامساً:** برمجة السحب الرأسي للتاسكات لإعادة الترتيب داخل نفس العمود بصفحة المشروع الأساسية وحفظ الـ Index الجديد بـ Firestore.
