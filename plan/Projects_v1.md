# 🚀 خطة التحديث v17.0 — ضبط نظام التوجيه البصري وإيقاف التكرار البرمجي (UI Direction & State Stability Plan)

تستهدف هذه الخطة إصلاح مشكلة تكرار تحديث الشاشة التلقائي، وإعادة ضبط اتجاهات عناصر تحكم التقويم، مع دمج زر الإجراء السريع للمهام، وبناء نظام توجيه فوري للمستخدم لمعرفة مهامه الحالية والتالية مباشرة من الواجهة الموضحة في image_e7dabb.png.

---

## 🎨 1️⃣ إصلاحات واجهة التقويم والتحكم السريع (Calendar UI & Action Triggers)

### أ. تعديل اتجاه زرار دخول التقويم (Navigation Icon Correction)
* **المشكلة:** سهم أو أيقونة زرار الدخول إلى التقويم تظهر بشكل معكوس هندسياً مقارنة باتجاه حركة المستخدم داخل النظام الداكن.
* **الحل:** إعادة ضبط خصائص الـ CSS الخاصة بالأيقونة (مثل `transform: rotate()` أو تعديل كلاس السهم) ليتجه المسار بشكل صحيح ومريح بصرياً.

### ب. زر الحسم السريع "تحويل لـ Done" (Instant Done Button)
* **خاص بتفاصيل التقويم فقط:** يتم إضافة زر إنهاء صغير وأنيق (أيقونة Checkmark مدمجة) يظهر **فقط وحصرياً** داخل كروت التاسكات المعروضة في صفحة التقويم الداخيلية.
* **السلوك اللحظي:** عند ضغط هذا الزر، تتحول حالة التاسك فوراً إلى "تم الانتهاء Done"، وينتقل الكارت صامتاً إلى عمود المكتملين مع تقليل شفافيته تلقائياً، دون الحاجة لفتح تفاصيل المهمة أو سحبها يدوياً.

## 🧠 2️⃣ بناء سكشن الإرشاد "أنا واقف فين؟" (The Context & Next-In-Line Feed)

* **الموقع والمفهوم:** يتم حجز مساحة مدمجة وعالية الكثافة (High-Density UI) بجانب منطقة الشغل والتاسكات (مثل الهيكل المعروض في قائمة "جاري التنفيذ" بـ image_e7dabb.png).
* **الوظيفة البصرية:** يعرض هذا القسم بوضوح شديد سطرين ذكيين للمستخدم أثناء اندماجه في العمل:
  1. 📍 **أنا واقف فين حالياً:** (يستعرض اسم التاسك والمشروع الحاليين اللذين يتم احتساب وقت البومودورو عليهما الآن).
  2. ⏭️ **الذي عليه الدور:** (يجلب تلقائياً التاسك التالية في قائمة الأولويات لنفس المشروع ليكون المستخدم على دراية بالخطوة القادمة دون تشتيت).

## 🛠️ 3️⃣ الحل الجذري لمشكلة الـ Reload المتكرر (Firestore Snapshot Cleanup)

* **تشخيص المشكلة القائمة:** تكرار عمل ريلود أو وميض سريع (Quick Blink/Reload) للشاشة أثناء فتحها يحدث بسبب عدم إغلاق مستمعي البيانات اللحظية القدامى (`onSnapshot`) عند الانتقال بين الصفحات أو عند تحديث حقول الساعات، مما يسبب حلقة استدعاءات برمجية مكررة (Infinite Listener Loops) تعيد بناء الواجهة عشوائياً كما تم رصده في image_e7dabb.png.
* **العلاج التقني الصارم:** 
  1. إجبار الكود على عمل تنظيف كامل (`unsubscribe()`) لكافة مستمعي Firestore النشطين فور مغادرة الصفحة أو قبل فتح مستمع جديد.
  2. التأكد من أن دالة جلب البيانات لا يتم استدعاؤها إلا عند حدوث تغيير حقيقي في المستندات الأساسية فقط، مع تفعيل الـ `Layout Guard` لمنع اهتزاز الشاشة.

## 📋 4️⃣ خطوات التنفيذ المحددة (Action Items لـ Claude)

- [ ] **أولاً:** تعديل تنسيق سهم زر دخول التقويم ليكون في اتجاه الحركة الصحيح دون انعكاس.
- [ ] **ثانياً:** إضافة كود الزر الصغير `Done Button` داخل قالب كروت التاسكات في التقويم فقط، وربطه بدالة تحديث الحالة الفورية بـ Firestore.
- [ ] **ثالثاً:** تصميم وبناء السكشن الإرشادي المدمج "أنا واقف فين" بجانب حاوية المهام النشطة لتسهيل التوجيه والمتابعة اللحظية أثناء العمل الفعلي.
- [ ] **رابعاً:** تتبع ملفات الربط بقاعدة البيانات، وتطبيق دالة الـ `Clean-up` لجميع الـ Snapshots لإيقاف الـ Quick Reload المتكرر وتثبيت حالة الواجهة تماماً.
