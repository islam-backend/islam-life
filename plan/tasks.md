# 🚀 خطة التحديث v21.0 — إصلاح تداخل تكسير واجهة المشاريع أثناء السحب (Drag & Drop Layout Overflow Fix)

تستهدف هذه الخطة علاج المشكلة البصرية والبرمجية المعروضة في image_e7627c.png، حيث يحدث تداخل (Overflow) وتشويه لهيكل كروت المشاريع الكبيرة أثناء إعادة ترتيبها أفقياً.

---

## 🎨 1️⃣ معالجة الـ CSS والـ DOM أثناء عملية السحب (Drag Layout Alignment)

### أ. تحجيم عنصر الـ Placeholder والـ Ghost Element
* **المشكلة:** عند سحب الكارت الكافي للمشروع في image_e7627c.png، العنصر الوهمي البديل (Placeholder) والعنصر المسحوب لا يلتزمان بالـ Width أو الـ Box-sizing الفعلي، مما يتسبب في حشر الكروت وانزلاقها برة الواجهة.
* **الحل الهندسي:** 
  1. إجبار الـ Drag Container والـ Clone Element على تبني خاصية `box-sizing: border-box;` بشكل صارم.
  2. تثبيت خصائص الـ `flex-shrink: 0;` لعناصر المشاريع المجاورة لمنع انضغاطها أو كسر أبعادها الحادة أثناء حركة السحب.

### ب. منع الـ Overflow وإحكام الحاوية الأفقية (Horizontal Container Guard)
* تفعيل خاصية حظر التمدد العشوائي على الحاوية الأفقية الأم الكبرى التي تجمع كروت المشاريع عبر ضبط الـ Display الخاص بها ليكون متزناً (مثل `display: flex;` مع `align-items: flex-start;`).
* قفل وتصفية خصائص الـ `z-index` لعنصر المشروع النشط (المسحوب حالياً) ليرتفع بسلاسة فوق الكروت الأخرى بدون أن يؤثر على تموضعها الفيزيائي في الشاشة أو يتسبب في تراكب النصوص المشوهة كما في image_e7627c.png.

## 🛠️ 2️⃣ خطوات التنفيذ المحددة (Action Items لـ Claude)

- [ ] **أولاً:** تتبع الكود البرمجي المسؤول عن مكتبة أو دالة السحب والإفلات (Drag and Drop) لكروت المشاريع والعملاء في واجهة التقويم.
- [ ] **ثانياً:** تعديل التنسيقات البرمجية المضافة ديناميكياً أثناء السحب (`dragging class` أو الـ `sortable-placeholder`) وتثبيت أبعاد العرض والارتفاع لها لتطابق الكروت الأصلية تماماً.
- [ ] **ثالثاً:** إصلاح أزمة تراكب النصوص والعناصر في image_e7627c.png بإضافة `overflow: hidden;` مؤقت على الكروت أثناء السحب، وضمان عودة الـ Layout لوضعه المستقر بمجرد الإفلات (Drop).
