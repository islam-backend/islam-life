# 🚀 خطة التحديث v3.0 — إضافة لوحة المؤشرات الذكية وتتبع المشاريع (islam.walied)

هذه هي الخطة التنفيذية لترقية النظام وإضافة تابة **"الداشبورد الرئيسية"** لتوفير نظرة علوية شاملة على مستوى تقدم الأعمال (Progress Tracking)، مع إتاحة التنقل السريع المباشر للمشاريع والمهام.

---

## 🎨 التحديثات البصرية ونظام التصميم (Dashboard UI UIX)

للحفاظ على هدوء وفخامة ثيم **PhpStorm New Dark UI**، سيتم تصميم عناصر الداشبورد كالتالي:
*   **كروت المؤشرات (Stat Cards):** صناديق بخلفية `#2B2D31` وحدود رفيعة `#3F424A` تحتوي على أرقام كبيرة مضيئة باللون الأزرق `#3574F0` أو الأخضر `#3DB981` لإبراز الإحصائيات[cite: 1].
*   **مؤشرات التقدم الـ Progress Bars:** خطوط رفيعة دائرية أو أفقية بخلفية داكنة جداً `#1E1F22`، ويمتد داخلها شريط ملون باللون الأخضر `#3DB981` أو الأصفر بناءً على نسبة إنجاز المشروع[cite: 1].
*   **الرسوم البيانية المصغرة (Sparklines):** استخدام تأثيرات CSS أو مكتبة خفيفة لعرض منحنى بسيط لإنتاجيتك وعدد المهام المكتملة آخر 7 أيام.

---

## 🏗️ البنية المعمارية وهندسة التصفح (Navigation & SPA Flux)

### 1️⃣ تعديل الـ Sidebar (القائمة الجانبية):
*   إعادة تفعيل تابة **"الداشبورد الرئيسية 📊"** لتكون هي الصفحة الافتراضية الأولى عند فتح النظام.
*   نقل التبويب الحالي ليكون باسم **"إدارة العملاء 💼"**[cite: 1].

### 2️⃣ آلية التنقل الذكي (The Navigation Flow):
*   عند الضغط على أي مشروع داخل "صفحة الداشبورد"، يقوم الـ JavaScript خلف الكواليس بمحاكاة الضغط على العميل التابع له المشروع، ثم فتح صفحة الكانبان الخاصة بهذا المشروع فوراً (Deep Linking داخل الـ SPA).
*   زر الرجوع الذكي (`toolbar-back-btn`) سيتعرف ديناميكياً على مصدر الزيارة: إذا دخلت للمشروع من الداشبورد، عند الضغط على رجوع سيعيدك للداشبورد مباشرة بدلاً من صفحة العملاء[cite: 1].

## 🛠️ جدول مراحل تنفيذ التحديث v3.0

### 🗓️ المرحلة الأولى: هيكل الواجهة الجديدة (Layout & Components)
* [ ] **تعديل HTML (`index.html`):** إضافة سكشن جديد `#dashboard-section` بـ `display: none;` كجزء من الـ SPA[cite: 1].
* [ ] **تصميم قسم المؤشرات السريعة (Counter Grid):** 4 كروت علوية تعرض:
    1. إجمالي العملاء النشطين.
    2. المشاريع الجارية حالياً.
    3. المهام المتبقية في عمود "المطلوب" (Todo) عبر كل المشاريع[cite: 1].
    4. إجمالي المهام المكتملة (Done)[cite: 1].
* [ ] **تصميم قسم "المشاريع الحالية" (Active Projects Grid):** شبكة عرض لكروت المشاريع الجارية فقط، تظهر اسم المشروع، اسم العميل، والـ Progress Bar الخاص به.

### 📊 المرحلة الثانية: الحسابات البرمجية والـ Realtime Aggregations
* [ ] **برمجة الـ الـ Counters ديناميكياً:**
    * الاستفادة من الـ Snapshots الحالية لعمل Loops سريعة تحسب إجمالي المستندات[cite: 1].
    * حساب نسبة إنجاز كل مشروع برمجياً بمعادلة بسيطة:
      $$\text{Progress \%} = \left( \frac{\text{Tasks Count in Done}}{\text{Total Tasks Count in Project}} \right) \times 100$$
* [ ] **تحديث الـ Progress Bars لحظياً:** ربط الـ Progress Bar بالداتابيز، بحيث لو قمت بسحب مهمة إلى عمود "تم الانتهاء" (Done) في صفحة الكانبان، تتحدث نسبة المشروع في الداشبورد تلقائياً في نفس اللحظة[cite: 1].

### 🔗 المرحلة الثالثة: ربط حركة التنقل الفوري (Deep Clicking)
* [ ] إضافة الـ Custom Data Attributes لكروت المشاريع في الداشبورد مثل (`data-client-id` و `data-project-id`).
* [ ] كتابة الـ Event Listener في `app.js` عند الضغط على كرت المشروع:
    1. يقرأ الـ IDs الخاصة بالعميل والمشروع.
    2. يقوم بتحديث متغيرات الحالة (State) للتطبيق.
    3. يخفي سكشن الداشبورد ويظهر سكشن الكانبان الخاص بالمشروع فوراً مع تفعيل حركة فخمة (Fade-in)[cite: 1].
* [ ] ضبط منطق زر الرجوع لحفظ الحالة السابقة (History Stack مبسط بالـ JS).

## 🗄️ هل سنعدل على Firebase Schema؟
*   **لا يوجد تعديل جذري:** الهيكل الحالي المعتمد على الـ Subcollections ممتاز ومثالي جداً[cite: 1].
*   **الإضافة الوحيدة:** سنقوم بإضافة حقل اختياري في مستند المشروع (Project Document) باسم `progressPercentage` يتم تحديثه تلقائياً بواسطة الـ JS عند تعديل المهام، لسهولة قراءته في الداشبورد مباشرة دون الحاجة لعمل جلب (Fetch) لكل المهام في كل مرة تفتح فيها الداشبورد، لضمان السرعة القصوى واستهلاك أقل للـ Quota[cite: 1].
